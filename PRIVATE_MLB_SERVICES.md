# MLB services with restricted or unclear access

Reviewed **2026-11-09**. This note separates whether MLB publishes interface documentation, whether an anonymous request returned data, and whether the service is available to a given user or partner. A public schema does not grant access to every operation.

## Findings

MLB does **not** make every service private. The captured Stats API specification lists 200 GET operations; 160 were checked anonymously across all 34 represented operation families. Of those, 129 returned JSON, 22 returned an Okta login response with HTTP 401, seven returned JSON errors and two returned non-JSON 404s. Forty documented operations were not directly probed. The current public [`/v3/api-docs`](https://statsapi.mlb.com/v3/api-docs) specification exposes paths and response schemas. MLB's [authentication and authorization documentation](https://docs.statsapi.mlb.com/getting-started/authentication-authorization) is public as a documentation page, but the live documentation interface itself has an authentication gate. These facts mean route documentation can be public while selected data operations remain access-controlled.

The clearest access boundary is on high-detail tracking and analytics. In anonymous checks, the documented raw and parsed analytics routes, game GUID listing, per-play analytics, skeletal file listing, biomechanics, bat tracking, weather detail, and several other operations returned HTTP 401 with an Okta login response. This establishes that those tested requests required authentication at the time of review. It does not identify which credentials, account groups, club agreements, or licenses grant access.

## What the public material says about private distribution

MLB engineering and Google Cloud accounts describe club/partner distribution explicitly. The 2020 Hawk-Eye article says processed tracking data is distributed to clubs and MLB partners through the Stats API application; the 2022 account describes data in PostgreSQL and Bigtable with nightly Cloud Storage and BigQuery exports; the 2024 account describes APIs feeding MLB products and club BigQuery environments. None publishes a public login, credential-issuance flow, bucket path, database hostname, table names, or an entitlement promise for an unaffiliated caller.

The Stats API docs publish request parameters and response schemas for restricted analytics routes. However, raw/parsed examples and tracking guides do not make the underlying tracking payload anonymous. For example, the OpenAPI `AnalyticsRestObject` describes tracked events, ball segments, target positions, calibration, weather and video fields, while an anonymous request for the tested play's analytics returned 401. Treat the OpenAPI file as a visible interface contract, not evidence of successful access to every documented field.

## Access answer

Some MLB services are accessible anonymously, including many Stats API operations, Savant searches, public video metadata/playback for tested clips, and selected Film Room GraphQL queries. Other documented endpoints returned 401, especially detailed tracking and selected advanced-stat operations. Some services require a bearer token according to the client source; a credentialed request is not part of this audit. Club BigQuery and other partner delivery are described publicly but require their own access arrangements, which the sources do not document for general users.

There is no evidence here that private MLB services can be accessed without authorization. Nor do these observations establish that every 401 endpoint is restricted to clubs: MLB may provide credentials or licenses through a process not covered by public documentation. The precise eligibility, application path and terms for raw tracking, private analytics, live feeds and partner datasets remain unspecified in the sources reviewed.
